## 1. 项目概述

**EdgeHotel-Agent**：在 8GB 显存消费级工作站上运行的端侧酒店私域运营 Agent。差异化三件套：**隐私离线**（全本地推理，数据不出机器）+ **行业模板**（hotel/restaurant 条件装配）+ **静默失败治理**（如实降级不编造）。

| 技术栈 | 选型 |
|---|---|
| 运行时 | Java 17 · Spring Boot 3 (WebFlux) · AgentScope Java 2.0.4（HarnessAgent + OpenAI 兼容 Starter） |
| 推理 | LM Studio（OpenAI 兼容端点 :1234/v1），模型矩阵见 §7 |
| 持久化 | SQLite 单文件（每商家一库 = 租户隔离），7 张表 |
| 标准接入 | MCP Java SDK 2.1.0（stdio + Streamable HTTP 双传输） |
| 容器 | Docker 多阶段自包含构建（agentscope SNAPSHOT 经 m2-vendor 离线解析） |

## 2. 系统架构

```
渠道层（4 渠道）          控制台 console/index.html
   │ 验签/解密/频控/审计        │
   ▼                          ▼
Controller 层 ──► AgentRunner 编排循环 ──► ToolRegistry（工具 SPI）
   │                │ 记忆注入 │ 信号量+超时        │ 条件装配（EH_TEMPLATE）
   │                ▼                              ├─ hotel 5 工具
   │         LM Studio :1234/v1                    ├─ restaurant 6 工具
   │         （gemma/30B/9B 模型矩阵）              └─ McpBridgeTool（EH_MCP_ENABLED，桥接 mcp-server）
   ▼
Store 层（SQLite 7 表）── 防线：StartupPreflight（启动）+ RuntimeGuard（每 5 分钟）
mcp-server（8611 进程/8601 HTTP）──► aurora 真实 PMS（8102-8108，租户头）
```

**关键设计决策**：
- **双 Agent 路径**：自定义 AgentRunner（编排主链路，本档 §4）与 HarnessAgent（/api/chat，AgentScope 会话/压缩），compaction trigger 30 / keep 10
- **工具 SPI**：`Tool` 接口（name/description/jsonSchema/run/isSensitive），`ToolResult.standard/empty/error` 公开工厂——外部行业包即可实现模板
- **模板 SPI**：`TemplateDescriptor`（systemPrompt），`EH_TEMPLATE` 条件装配工具集与提示词
- **写类工具审批语义归运行时**：MCP Server 只提供执行；Approval Gate 在 AgentRunner 内拦截
- **推理串行**：Semaphore(1)（治理红线：LM Studio 并发会叠 KV 并可能 500）

## 3. 数据模型（SQLite，data/edgehotel.db，每商家一库）

| 表 | 列 | 用途 |
|---|---|---|
| `approvals` | id PK, session_id, tool_name, args_summary, status(pending/granted/denied), operator, reason, ts | 审批留痕（写工具 100%） |
| `silent_failures` | id AI, session_id, tool_name, category, root_cause, recovery, ts | 静默失败台账 |
| `memories` | id AI, scope_type, scope_id, content, embedding BLOB, source_step, ts | 跨会话记忆（向量） |
| `eval_cases` | id AI, trajectory_hash UNIQUE, session_id, tool_name, args_summary, category, verdict, recovery, hits, ts | 失败轨迹→回归用例（hash 去重） |
| `tickets` | id AI, kind, ref, session_id, guest, location, content, status(OPEN/DRAFT), ts, **tenant** | 投诉工单/话术草稿 |
| `channel_messages` | id AI, channel, peer, direction, session_id, content, status, ts, **tenant** | 渠道消息审计 |

索引：idx_approvals_status / idx_failures_category / idx_memories_scope / idx_eval_hash。**租户列幂等补列**（存量库自动 ALTER）。备份：`backup-edgehotel-db.ps1`（14 份保留，已入守卫）。

## 4. HTTP 接口参考（主应用 :8600）

### 4.1 编排与智能

| 接口 | 入参 | 出参 |
|---|---|---|
| `POST /api/agent/ask` | `{question, userId?, sessionId?}` | `{question, answer, tool_calls[], verifier_warnings[], approvals[]}` |
| `GET /api/agent/tools` | — | `{template, tools:[{name, sensitive, description}]}`（模板切换验证入口） |
| `POST /api/chat` | HarnessAgent 路径（AgentScope 会话/压缩） | — |
| `GET /api/health` | — | `OK` |
| `POST /api/complaint/detect` | `{text}` | `{isComplaint, category, confidence, reason}`（解析失败自动规则兜底） |
| `GET /api/rag/retrieve?q=&k=3` | — | `{question, hits:[{id,title,score}]}` |
| `POST /api/rag/ask` | `{question}` | 检索 Top-3 注入 → Agent 回答 |
| `POST /api/memory/add` | `{scope_type, scope_id, content, source_step}` | `{ok, memory_id}` |
| `GET /api/memory/recall?scope_type=&scope_id=&query=&top_k=5` | — | `{items:[{content, sourceStep, ts}]}` |

### 4.2 治理与运营

| 接口 | 说明 |
|---|---|
| `GET /api/approval/pending` / `GET /api/approval/all` | 审批队列 / 全量留痕（ApprovalRecord：id/sessionId/toolName/argsSummary/status/operator/reason/ts） |
| `POST /api/approval/{id}/grant` `{operator}` | **放行即执行**：翻转状态 → 按存储参数执行工具 → 返回 `execution:{tool,ok,output}` |
| `POST /api/approval/{id}/deny` `{operator,reason}` | 拒绝留痕 |
| `GET /api/verifier/ledger` | 静默失败台账 |
| `GET /api/eval/cases` | 回归用例集（trajectoryHash 去重 + hits） |
| `GET /api/tickets?kind=&status=` | 投诉工单（OPEN）/话术草稿（DRAFT），带租户 |
| `GET /api/ops/overview` | 运行视图：模板/内存/模型加载态/渠道计数/工单存量/运行时长 |

### 4.3 渠道

| 接口 | 说明 |
|---|---|
| `POST /api/channel/webhook` | 通用渠道：头 `X-EdgeHotel-Timestamp`+`X-EdgeHotel-Signature`（HMAC-SHA256(secret, "ts.body")），体 `{peer,text,externalSessionId?}`；echo 模式回环 |
| `GET\|POST /api/channel/feishu/callback` | 飞书：URL 验证（challenge 回显）+ v2 事件；头 `X-Lark-Signature/Timestamp/Nonce` |
| `GET\|POST /api/channel/wecom/callback` | 企微：URL 验证（回解密明文）+ XML 信封；参数 `msg_signature/timestamp/nonce` |
| `POST /api/channel/dingtalk/callback` | 钉钉：头 `timestamp`+`sign`（HMAC-SHA256）；恒 200 语义 |
| `GET /api/channel/messages?channel=&peer=&direction=` | 审计查询（最近 100 条） |
| `GET /api/channel/messages/stats` | 渠道决策点计数（received/verified/echo/drop_*） |

### 4.4 MCP Server（:8601 或 stdio）

JSON-RPC 方法：`initialize`（返回 Mcp-Session-Id，协议 2025-06-18）→ `notifications/initialized` → `tools/list` / `tools/call`。6 工具：hotel_room_status / hotel_price_quote / hotel_booking_lookup / member_profile_query / complaint_escalate / marketing_copy_generate。数据源：`--pms demo [--data json]` / `--pms aurora --pms-url <host> --pms-tenant 1`；鉴权 `--auth-token`（Bearer）。结果含 text + structuredContent；工具执行失败 isError=true。冒烟：stdio 9 项 / HTTP 8 项 / aurora 8 项 / 鉴权 9 项。

## 5. 行业工具清单

**hotel**（`EH_TEMPLATE=hotel`，默认）：

| 工具 | 敏感 | 参数 | 防线语义 |
|---|---|---|---|
| hotel_room_status | 否 | date | 未知日期 UNKNOWN_DATE（不编造） |
| hotel_price_quote | 否 | room_type | 未知房型如实 |
| hotel_booking_lookup | 否 | order_id | NOT_FOUND 如实 |
| complaint_escalate | **是** | guest_name, issue, room_no?, severity? | 审批拦截 → 放行即执行 → tickets 落库 |
| marketing_copy_generate | **是** | scenario, guest_name, room_type?, tone? | 审批拦截 → DRAFT 落库 |

**restaurant**（`EH_TEMPLATE=restaurant`）：

| 工具 | 敏感 | 参数 | 防线语义 |
|---|---|---|---|
| restaurant_table_status | 否 | date, slot?, table_type? | UNKNOWN_DATE 明示数据覆盖范围 |
| restaurant_menu_price | 否 | dish_name | 未知菜品如实 |
| restaurant_order_lookup | 否 | order_id | NOT_FOUND 如实 |
| restaurant_member_profile | 否 | member_id | 脱敏（仅等级+偏好） |
| restaurant_complaint_escalate | **是** | guest_name, issue, table_no? | 审批拦截 → tickets 落库 |
| restaurant_marketing_copy | **是** | scenario, guest_name | 审批拦截 → DRAFT 落库 |

## 7. 质量与测试

- **单元测试**：13 项（WebhookSignature KAT×4 / ChannelRateLimiter×3 / RestaurantData×6），`mvn test` 零模型依赖
- **回归资产**：`eval-regression.py`（hotel 16 / restaurant 12 轮，静默失败率 0.0%）+ `channel-regression.py`（四渠道 17 断言）+ `mcp-smoke.py`（stdio 9）/ `mcp-smoke-http.py`（8）/ `mcp-smoke-aurora-live.py`（8）/ `mcp-smoke-auth.py`（9）
- **每日守卫**：`nightly-guard.ps1` = 构建防线 → 单测 → MCP 冒烟 → 渠道回归 → 备份 → 资源体检（schtasks 注册命令见脚本头）
- **模型加载**：`load-model.ps1 -Model <别名>`（红线前置拒绝 + 治理参数内置）

## 8. 部署与运维

- **本机**：`build.ps1`（停应用→构建→产物校验）→ `load-model.ps1` → 起 jar → health/ops 确认
- **容器**：`docker compose --env-file .env up -d`（可选 `--profile mcp`）；healthcheck 内建；数据卷 edgehotel-data / mcp-data
- **备份/恢复**：`backup-edgehotel-db.ps1` → 覆盖 `data/edgehotel.db`（演练 PASS）
- **升级**：停应用 → build.ps1 → 重新 up → health + ops/overview 确认（数据卷不受影响）
- **红线**：内存 >85% / 可用 <3.5GB / 引擎 ≤2 / 单模型文件 ≤20GB（详见治理规范）

## 9. 已知边界（如实声明）

1. P95 首响：9B（VLM+思考-only）本机不可用；gemma 分类 P95 6.2s（<3s 需 0.5B 快筛路径或 GUI 关 Reasoning）
2. 渠道适配器为离线夹具自测，真实凭据端到端待平台申请
3. 餐饮工单/话术落库闭环，真实工单系统/消息通道为试点期工作
4. F1=0.98 为 40 样本点估计，试点期持续扩充
5. 两级分类已数据驱动否决（0.5B 置信度无区分度），重启条件已记录
