## 三、系统构成（当前架构）

### 3.1 双工程

```
D:\AI\edgehotel-agent\
├── 主应用 edgehotel-agent（Spring Boot 3 + AgentScope Java 2.0.4，端口 8600）
│   ├── AgentRunner 编排循环（记忆注入 → 工具 → Verifier → 审批门，推理串行信号量）
│   ├── 行业模板：hotel（5 工具）/ restaurant（6 工具）—— EH_TEMPLATE 条件装配
│   ├── MCP 数据源模式：EH_MCP_ENABLED=true 时读工具桥接 mcp-server（schema 真源在 MCP 侧）
│   ├── 渠道层：webhook / 飞书 / 企微 / 钉钉（验签-解密-映射-频控-审计统一模式）
│   └── 防线体系：StartupPreflight（启动）+ RuntimeGuard（每 5 分钟）+ chat 超时 + 频控
└── mcp-server（MCP Java SDK 2.1.0，stdio + HTTP 8601，独立打包）
    └── 双传输 × 双数据源：demo 内置 / 外置 JSON / aurora 真实 PMS（租户头+多服务路由+脱敏）
```

### 3.3 渠道矩阵（4/4 全通）

| 渠道 | 验签/加密 | 出站 | 特性 |
|---|---|---|---|
| 通用 Webhook | HMAC-SHA256 + ±5min 防重放 | 同步应答 | 平台无关 |
| 飞书 | 官方 FeishuCrypto（AES + SHA-256） | IM API（凭据即通） | URL 验证/v2 事件/自环防护 |
| 企业微信 | 官方 WeComCrypto（SHA-1 排序 + AES-CBC） | IM API（凭据即通） | XML 信封/MsgId 幂等 |
| 钉钉 | 官方 DingTalkCallbackCrypto（HMAC-SHA256） | **sessionWebhook 零凭据** | 单聊/群聊 peer 规则/恒 200 |

统一接线：确定性会话映射 → 频控（per-peer 30/min，429）→ 审计落库（channel_messages，租户标记）→ 计数器（stats 端点，静默丢弃可观测）。

## 五、部署与运维形态

- **新商家接入**（<1 天）：复制 `.env.example` → 填 `EH_TENANT_ID`/渠道变量 → `docker compose --env-file .env up -d`（可选 `--profile mcp`）
- **每日守卫**：`scripts/nightly-guard.ps1`（schtasks 注册命令在脚本头）——构建→单测→冒烟→渠道→备份→体检，日志落 `logs/`
- **模型加载**：`scripts/load-model.ps1 -Model <别名>`（红线前置拒绝 + 治理参数内置）
- **备份**：`backup-edgehotel-db.ps1`（14 份保留），已挂入守卫；恢复演练 PASS
- **升级流程**：停应用 → `build.ps1`（产物校验）→ 重新 up → health + ops/overview 确认
- **环境变量**：全部配置外置（`.env.example` 全清单：端口/模型/模板/租户/渠道/频控/守卫/MCP/飞书/企微/钉钉）
