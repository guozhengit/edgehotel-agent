## 二、验证结果（实测）

### ① 投诉识别（出口：F1 ≥ 0.8）→ **F1 = 1.000 PASS**（9B 快路径）
- 测试集 20 条（10 投诉 + 10 非投诉，含卫生/设施/服务/价格/噪音各类），TP=10 FP=0 FN=0，Precision/Recall 均 1.000
- 低置信度（<0.4）自动保守判投诉；模型不可用时规则兜底（宁误报不漏报）

### ② 静默失败 Verifier（出口：静默失败率 < 5%）→ **实弹通过**
- 正常查询：无警告（2026-10-30 房态 ✓）
- 未知日期（2026-11-05）：工具返回 EMPTY → Verifier 标记 silent_failure → 台账 +1 → 回填"【校验警告 empty_result】…人工核对" → 模型回答改为"无法获取该日期房态，建议联系前台"（**未照抄误导数据**）
- ERROR 路径：工具异常 → 显式失败（代码路径就绪）

### ③ Approval Gate（出口：100% 敏感操作留痕）→ **实测通过**
- 场景"投诉升级人工"：模型自动调用 complaint_escalate → **被拦截不执行** → 审批 ID AP-0001 → 回答"已转交人工（审批ID）"
- API 全链路：GET pending（1 条）→ POST grant（AP-0001 granted）→ 再触发（AP-0002）→ POST deny（denied）→ 留痕总数 2
- 所有记录含 operator/时间戳，可审计

### ④ 附带修复（M1-1 登记项）
- **日期幻觉**：system prompt 加"日期用今天或客人提供值，严禁虚构"→ 实测"明天"= 2026-10-30、"10月31号"= 2026-10-31，**不再虚构 2023**
- **查不到却答可订**：HotelData 未知日期不再返回默认"可订"，改 EMPTY（由 Verifier 接管）
- **尾号直传**：booking 工具描述补"客人只报手机尾号时可直接传 phone"；实测模型仍保守先要订单号（可接受，防误查）

## 三、关键排障记录（重要资产）

**LM Studio 的 max_tokens 兼容坑**：`/v1/chat/completions` 传 `max_tokens` 字段时**返回空 content**（HTTP 200 但 content=""），去掉该字段立即正常。影响面：所有 Java 请求须省略 max_tokens。已从 LlamaComplaintDetector 移除。**此坑可能导致此前对 GLM-4.7-Flash / Qwen3.5-9B"不可用"的误判需复核**（当时测试均带 max_tokens）。
