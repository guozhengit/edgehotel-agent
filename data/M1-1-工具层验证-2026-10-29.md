# M1-1 工具层与编排循环 — 验证记录（2026-10-29）

## 一、交付物（`D:\AI\edgehotel-agent` 新增）

```
src/main/java/com/edgehotel/agent/agent/
├── Tool.java                  # 工具抽象（name/description/jsonSchema/run/isSensitive + ToolResult 三级状态）
├── ToolRegistry.java          # 注册表（Spring 自动收集 Tool bean → OpenAI tools 参数）
├── HotelData.java             # 极光酒店示例数据层（demo 口径，全部标注"示例"）
├── HotelRoomStatusTool.java   # 工具1/3：hotel_room_status（查房态）
├── HotelPriceTool.java        # 工具2/3：hotel_price_quote（查房价/含早/会员价）
├── HotelBookingTool.java      # 工具3/3：hotel_booking_lookup（查订单）
└── AgentRunner.java           # function-calling 编排循环（规划→工具→回填→回答，max 3 轮）
controller/AgentController.java # POST /api/agent/ask
```

编排原理：调 LM Studio `/v1/chat/completions`（带 tools）→ 解析 `tool_calls` → 执行工具 → 以 `role=tool` 回填 → 再调，直至模型不再调用。`/no_think` 保持关闭思考。

## 二、验证结果（Qwen3-30B-A3B，4 场景实测）

| 场景 | 触发工具 | 耗时 | 质量 |
|---|---|---|---|
| 房态+价格（10/30 晚） | ✅ `hotel_room_status` + `hotel_price_quote`（**双工具串联**） | 12s | ✅ 回答整合正确（标准间¥599/豪华¥899/套房剩2间¥1599/会员价¥539） |
| 豪华房今日价 | ✅ `hotel_price_quote` | 6s | ⚠️ 日期幻觉：模型传了 `2023-10-05`（应默认今天）；回答如实标注"示例" |
| 手机尾号查订单 | ⚠️ 未触发（要订单号） | 2s | 对话行为合理，但 6688 符合"后4位"格式本可直接查 |
| 官方直订话术 | ✅ 无工具（正确） | 6s | ✅ 4 点话术（会员价/沟通/安全/灵活） |

**核心闭环成立**：模型能根据问题自主选择并串联工具、回填结果后成回答；不需要工具的场景不误触发。

## 三、发现与 M1-2 改进项（已登记）

1. **日期幻觉**：模型虚构日期（2023-10-05）→ M1-2 在 system prompt 加"日期一律用今天（2026-10-29）或用户提供值，不得虚构"。
2. **尾号识别**：`hotel_booking_lookup` 描述补充"手机号后4位可直接传参（如 6688）"。
3. **Verifier 接入点**：`ToolResult` 已带 STANDARD/EMPTY/ERROR 三级状态 → M1-2 的静默失败检测（EMPTY+无异常 → 可疑）可直接挂 AgentRunner 回填后。
4. **Approval Gate 接入点**：`Tool.isSensitive()` 已定义（默认 false）→ 写入类工具（M2 对接 PMS 后）默认拦截。

## 四、下一步（M1-2）

Verifier（静默失败检测：EMPTY 判定 + 工具调用异常捕获）→ Approval Gate（敏感操作拦截队列）→ 投诉识别分类器（出口标准 F1≥0.8 的测试集构造）。
